Simulating hematopoietic phylogeny for SCM validation

Michael Tassia

2026-08-21

Overview

The objective of this notebook is to document our validation strategy for applying stochastic character mapping as a technique for reconstructing somatic genotype evolution given a phylogenetic tree, substitution model, and a data set of observed genotype states at the tips (see Bollback 2006 and Revell 2024). As a ground-truth somatic phylogeny data set does not yet exist, we will leverage simulation as a framework for validation.

This notebook will first describe the approach, key functions, and expected outcomes. Afterwards, additional layers of technical and biological variation will be introduced, including:

  • Sample size

  • Sequencing depth

  • Missing data

  • Collapsing branch lengths equal to 0

  • ISM-violation rate

Simulating hematopoiesis

We use the publicly available rsimpop package developed by Nick Williams at the Sanger Institute to simulate hematopoiesis under a birth-death model. This package implements the Gillepsie algorithm (see here for basic overview) to simulate cellular compartments under a distribution of user-defined parameters and is described in the supplementary information of Mitchell et al. 2022.

Here, we use rsimpop with parameters set following empirical estimates from the literature. Fitness coefficients manifest as bias toward symmetric division, and polygenic effects are assumed to be additive.

The libraries and functions used in this notebook are tracked in simphy_functions.R.

Distribution of fitness effects (DFE)

rsimpop encodes fitness as increased rates of symmetric division (i.e., birth) for clones bearing a driver mutation. Here, we draw fitness effects from a gamma distribution using the parameters described in Extended Data Fig 12 of Mitchell et al. 2022.

SEED <- 1212121

# DFE function

                             rate = 34,

Simulate HSC population

Using the DFE above, we can simulate hematopoiesis with stochastic introduction of driver mutations using the run_driver_process_sim() wrapper in rsimpop. This function has several important parameters which will be defined below:

  • simpop = NULL: Default setting; do not use a pre-existing simpop object

  • initial_division_rate = 0.1: Default setting; parameter estimate for HSCs during development; only effects early population growth phase.

  • final_division_rate = 1/365: Default setting; parameter estimate for HSCs during adulthood (concordant with the ABC estimates in Mitchell et al. 2022).

  • target_pop_size = 1e5: Default setting; mean parameter estimate for HSC population size at adulthood (concordant with the ABC estimates in Mitchell et al. 2022).

  • nyears = 50: User-defined age at collecting data. Validation will integrate across a distribution of ages.

  • fitness = fitnessFn: User-defined fitness function defined above

  • drivers_per_cell_per_day = 2.0e-3 / 365: User-defined count of driver mutations entering the population per day. This is the mean value estimated by ABC in Mitchell et al. 2022.

The functions get_subsampled_tree() and get_elapsed_time_tree() sample a subset of the total cellular phylogeny and re-scale the branch lengths given a fixed somatic mutation rate (i.e., \(16.8 \: \textrm{mutations per cell per year}\) estimated in Mitchell et al. 2022). Here, we simulate a population of \(P = 50,000\) HSCs, and subsequently sample \(N = 100\) tips.

# Simulation seed
initSimPop(SEED, bForce = TRUE)

# Run rsimpop
sim <- run_driver_process_sim(
  simpop                   = NULL,  
  initial_division_rate    = 0.1,  
  final_division_rate      = 1/365,   
  target_pop_size          = 1e5, 
  nyears                   = 80,  
  fitness                  = fitnessFn, 
  drivers_per_cell_per_day = 2.0e-3 / 365  
)

# Sample 100 cells from the HSC population
st <- get_subsampled_tree(sim, 100)

# Re-scale the phylogeny by mutations
st_mut <- get_elapsed_time_tree(st, 
                                mutrateperdivision = 0, 
                                backgroundrate = 16.8/365)

# Plot driver events on the phylogeny
plot_tree_events(st_mut,
                 cex.label = 0,
                 legpos = NULL)

The create_mut_df() function above takes the subsampled phylo object output by get_phylo_object() to create a data frame, where records correspond to “mutations”, and fields are defined as follows (in order):

  1. mutation_id <chr>: unique hash identifier for each record
  2. is_driver <lgl>: Boolean for whether record is a driver mutation
  3. selection_coefficient <dbl>: fitness coefficient, \(s\), if is_driver == TRUE; otherwise NA
  4. is_ism_violation <lgl>: Boolean for whether a record corresponds to an ISM violation
  5. n_origins <int>: Number of true origins for record
  6. edge <chr>: Edge number (in input phylo order) for record’s origin(s).
  7. [s1, s2, ..., sN+1] <dbl>: Remaining mutation array encoded with presence/absence (1 or 0) for whether the mutation is inherited by the tip. As an outgroup (without any mutation) is always introduced by get_subsampled_tree(), the number of fields in this component of the dataframe will equal \(N + 1\).

Thus, for \(N\) sampled tips and a total tree length of \(V\) (i.e., \(V\) mutations), the resulting data frame will be \((N + 6)\times V\). Note that introducing ISM violations will reduce the total matrix size, as introduce_ism_violations() merges records (see Simulating ISM violations below).

The combination of $edge and the mutation array patterns can be used to trace a mutation’s ancestry. For example:

Simulating sequence-read data

The output of create_mut_df() is then passed to the simulate_depth_and_ad() function to simulate sequence-read data. Default parameters are set such that they mimic the structure of “cleaned” data described in Coorens et al. 2025and/or modeled distribution parameters in Mitchell et al. 2022.

  • G: Matrix output by create_mut_df()

  • D_bar = 20: Target mean sequencing depth across the whole matrix

  • min_cov = 6: Lower depth bound a site must clear to pass QC (Sequoia-style min_cov)

  • max_cov = 250: Upper depth bound (excludes repeat/mapping-artifact loci)

  • site_sdlog = 0.5: Log-scale spread of per-site coverage bias (GC/mappability)

  • sample_sdlog = 0.3: Log-scale spread of per-sample library depth variation

  • theta = 8: Negative-binomial dispersion for residual (post-QC) depth noise

  • rho_max = 0.1: Beta-binomial overdispersion ceiling a site must clear (Sequoia snv_rho)

  • site_conc_shape = 4: Gamma shape for the distribution of per-site VAF concentration

  • site_conc_rate = 0.3: Gamma rate for the distribution of per-site VAF concentration

  • error_rate = 0.002: Sequencing/mapping error rate (alt reads at true hom-ref sites)

  • dropout_rate = 0.00: \(P(\textrm{complete allelic dropout} | \textrm{truly heterozygous site})\)

The simulate_depth_and_ad() function leverages will generate a list with the following slots:

  • $DP [stochastic]: Data frame containing simulated sequence depth at each site \(v\) per sample \(n\). Thus, \(\texttt{DP}_{nv} \sim \textrm{NB} (\mu_{nv} = \texttt{sample_factor}_n \times \texttt{site_factor}_v, \theta = \texttt{theta})\)

  • $AD [stochastic]: Data frame containing simulated variant allele depth at each site \(v\) per sample \(n\). For samples without mutation, \(\texttt{AD}_{nv} \sim \textrm{Binom}(n = \texttt{DP}_{nv}, p = \texttt{error_rate})\). For samples bearing mutation, \(\texttt{AD}_{nv} \sim \textrm{Binom}(n = \texttt{DP}_{nv}, p \sim Beta(\alpha = \beta = \frac{1}{2}\texttt{site_conc}_{nv}))\)

  • $site_factor [stochastic]: Vector containing scaling factors for each \(v\) simulated loci; \(\texttt{site_factor}_v \sim \textrm{LogN}_{tr} (\mu = 0, \sigma = \texttt{sigma_v}, a = \frac{\texttt{min_cov}}{\texttt{D_bar}}, b = \frac{\texttt{max_cov}}{\texttt{D_bar}})\)

  • $sample_factor [stochastic]: Vector containing scaling factors for each \(n + 1\) sampled tips (\(+1\) for the added outgroup); \(\texttt{sample_factor}_n \sim \textrm{LogN}_{tr} (\mu = 0, \sigma = \sigma_v, \alpha = \frac{\texttt{min_cov}}{\bar{D}}, \beta = \infty)\)

  • $site_conc [stochastic]: Vector containing symmetric beta distribution shape parameters used to simulate $AD at each \(NV\) site; \(\texttt{site_conc}_v \sim \Gamma_{tr}(\alpha = \texttt{site_conc_shape}, \beta = \texttt{site_conc_rate},a = \frac{(1 - \texttt{rho_max})}{\texttt{rho_max}},b = \infty)\)

  • $site_rho [deterministic]: Beta-binomial’s \(\rho\) parameter for each \(v\) site; \(\rho_{v} = \frac{1}{(1 + \texttt{site_conc}_v)}\)

  • $dropout [stochastic]: Boolean vector for whether a sample \(n\) experiences allelic dropout at site \(v\).

Testing the SCM framework on simulated data

Given the simulated tree and somatic variants above, SCM can be performed to infer the evolutionary history of somatic variants given simulated read data. Here, we’ll use the ground truth tree and just test the performance of SCM in reproducing each variant’s origin on the tree. In practice, SCM would be performed on a molecular phylogeny inferred from the VCF file above.

The three critical components for modeling somatic SNVs with SCM are (1) the phylogeny with branch lengths measured in substitutions per site, (2) the VCF file with somatic SNVs and their associated confidence metrics (PL scores), and (3) a genotype substitution model fit to the phylogeny. Below, we’ll use a substitution model fit with CellPhy to the ground truth tree and the observed data.

The CellPhy command for fitting unphased genotype substitution model (\(Q_{GT10}\)) parameters, \(\theta\) , is the following:

cellphy.sh \
    RAXML \
    --evaluate \
    --msa path/to/test_sim.vcf \
    --msa-format vcf \
    --model GT10+FO \
    --tree path/to/test_sim.nwk \
    --prefix cellphy \
    --threads 8 \
    --force perf_threads

Simulating ISM violations

To avoid changing the source code of Rsimpop to introduce infinite sites model (ISM) violations at the cellular dynamics phase, ISM violations will instead be introduced post-hoc. To accommodate the differential effects of mutations on the phylogenetic history of each simulated population, ISM violations will be introduced in a fashion that matches on fitness coefficients.

Background

To start with, we’ll use the principles of the birthday paradox to estimate the expected count of ISM violations to introduce into the population. Notably, we’ll assume a fixed mutation rate across the simulated genome, but in practice, mutation rate heterogeneity is a focal research topic in this study. The simulated history above assumes a fixed somatic mutation rate across the genome (\(\mu = 16.8 \: \textrm{SNVs per cell per year}\)), and here we estimate the expected count of ISM violations, \(x\), using,

\[E[\textrm{ISM Violations}] \approx \frac{(\sum_{i}v_i)^2}{2L},\]

where \(\sum_{i}v_i\) is the total branch length of the sub-sampled phylogeny (measured in mutations) and \(2L\) is the diploid genome size (\(\approx 6.4 \: \textrm{gigabases}\)). In the phylogeny simulated above, this evaluates to an expected 2 ISM violations.

Introducing ISM violations

Below, we’ll use both this predicted value and/or a fixed value to introduce ISM violations into the data frame output of create_mut_df(). A plot is generated reflecting an example for the ISM violations introduced on the phylogeny.

# Create a `violation_spec` df to specify ism violations for introduction
viols <- data.frame(n_origins = 2,
                    count = estimate_ism_violations(tr))

# Broadcase violations onto mut_mat
mut_mat.viol <- introduce_ism_violations(mut_df = mut_mat,
                         violation_spec = viols,
